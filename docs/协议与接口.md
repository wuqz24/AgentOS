# 协议与接口 v1

唯一 ABI 定义为 `agent-abi/src/lib.rs`。下列整数均按 RV64 原生小端布局传递；Wire 结构使用固定长度整数/数组，编译期检查大小，禁止隐含未初始化填充。

## 系统调用

| 编号 | 名称 | 主要参数/返回 |
| --- | --- | --- |
| 4000 | create | AgentCreateArgs 指针；成功返回数据区地址，失败返回负错误码 |
| 4001 | info | AgentInfo 输出指针；成功 0 |
| 4002 | tool_call | ToolRequest、ToolResponse 指针；返回工具状态 |
| 4003 | tool_list | 描述数组、容量；返回写入数量 |
| 4004 | context_push | ContextNode 指针；成功 0 |
| 4005 | context_query | 节点数组、最大数量；返回写入数量，取最近窗口 |
| 4006 | context_rollback | 当前窗口中需要保留的最早节点数 |
| 4007 | context_clear | 清空有效历史，保留单调序号和累计淘汰数 |
| 4008 | heartbeat_set | 10–60000 ms；0 等价停止 |
| 4009 | heartbeat_stop | 停止并清除未消费心跳 |
| 4010 | watch | 非零事件掩码 |
| 4011 | wait | 超时 0 表示无限等待，正值最多 300000 ms；返回事件位或负错误 |
| 4012 | unwatch | 移除事件订阅 |
| 4013 | finish | 释放 Context/IPC，状态 DONE |
| 4014 | receive | Message 输出指针；空队列 EAGAIN |
| 4015 | send | Message 输入指针；发送方由内核填入 |
| 4016 | clock | 客体原始时钟 ticks；频率由 get_system_status 返回 |

4093（映射冲突注入）、4094（损坏元数据尾记录）、4095（物理分配失败注入）仅为 `agent-test` 构建使用，不是正式 ABI。

## 数据结构与上限

| 结构 | 字节数 | 内容 |
| --- | ---: | --- |
| AgentCreateArgs | 32 | version、agent_type、quota（节点数）、heartbeat_ms |
| AgentInfo | 144 | identity、loop、Context 地址/长度/head/代数、消息与唤醒计数 |
| Param | 136 | key[24]、kind、number、text[96] |
| ToolRequest | 872 | version、request_id、name[32]、param_count、params[6] |
| ToolResponse | 2080 | status、request_id、timestamp_ms、len、json[2048] |
| ToolDescriptor | 384 | name[32]、params[192]、description[160] |
| ContextNode | 320 | seq、request_id、timestamp_ms、status、tool[32]、request[96]、result[160] |
| Message | 1584 | 源/目标 PID 与实例、kind、len、data[1536] |

定长文本需要 NUL 终止且剩余字节全为零，因此实际容量比数组大小少一字节；Message.data 和 ToolResponse.json 用 len 标明长度，不需要 NUL。参数 kind=1 为整数、2 为文本；bool 类型保留但没有公开工具使用。工具结果 JSON 支持 bool/null/数组等结构。

Context 配额为 1–192 个节点，总映射不超过 64 KiB。默认管理员 16 节点、受控工作负载 4 节点，边界场景 3 节点。首次 seq=0，next_seq 每次追加递增，回溯不复用序号。

## 工具表

`?` 表示可选参数，全部字段都必须通过内核类型与范围检查。

| 工具 | 参数 | 输出/限制 |
| --- | --- | --- |
| get_system_status | 无 | 进程/Agent/运行与阻塞计数、物理页、uptime、clock_hz |
| query_process | pid?, type?, status?, limit?, cursor? | type=agent/normal；status=ready/running/blocked；limit=1..6，默认4；next_cursor 为下一 PID |
| read_context | 无 | 当前调用者的 Context 元数据 |
| send_message | target_pid, target_instance, kind?, message | 同域 IPC；文本 <=95 UTF-8 字节，默认 kind=8 |
| set_file_attr | path,key,value | 现有文件；path<=27、key<=23、value<=63 字节；每文件最多8项 |
| delete_file_attr | path,key | 删除属性并更新索引；不存在返回 ESRCH |
| get_file_attrs | path | 稳定目录 ID、全部属性、版本；首次读取会登记现有文件 |
| query_files | filter,keyword?,mode?,limit?,cursor? | filter 如 `type=log,owner=4`，最多4个 AND 条件；mode=index/scan，limit=1..4；cursor 为下一稳定 ID |
| read_file_summary | path | 文件前缀摘要最多127 UTF-8字节、版本与cache_hit；无效UTF-8字节替换显示 |
| file_index_status | 无 | 文件数、版本、日志字节、epoch、损坏尾/无效bank检测 |

查询结果的 `elapsed_ticks` 只覆盖内核查询内部，不包含模型、串口或页面耗时。索引的 `index_payload_bytes` 是字符串有效内容，`index_allocated_bytes` 包含树节点和分配对齐。

## 事件、消息与错误

事件位：heartbeat=1，message=2，timeout=4，cancel=8。消息 kind：model_request=1，model_response=2，observation=3，goal=4，final=5，cancel=6，workload=7，event=8，hello=9。IPC 最多接受1..32，保留将来扩展。

受控负载接受 kind=7，数据为 `{"busy":false}` 或 `{"busy":true}`；kind=6 为退出。通过 send_message 工具控制时，message 参数是该 JSON 的文本形式。管理员只接受自身桥接进程发来的模型响应与取消。

| 错误 | 值 | 常见原因 |
| --- | ---: | --- |
| EPERM | -1 | 非 Agent、通信域不符、保留文件 |
| ESRCH | -3 | 目标进程/文件/属性不存在 |
| EAGAIN | -11 | 队列满或接收队列空 |
| ENOMEM | -12 | 预留物理页/消息容量失败 |
| EFAULT | -14 | 非法、非规范、未映射或权限不符的用户缓冲区 |
| EEXIST | -17 | 重复注册或目标地址已有映射 |
| EINVAL | -22 | 版本、参数、类型或取值非法 |
| ENOSPC | -28 | 目录/属性/输出/存储容量不足 |
| ENAMETOOLONG | -36 | SDK 文本字段超长 |
| ENOSYS | -38 | 未知工具或未实现系统调用 |
| EMSGSIZE | -90 | 消息/参数数量或序列化结果超限 |
| ETIMEDOUT | -110 | 预留错误码；当前 wait 超时以事件位返回 |
| ESTALE | -116 | 目标实例过期或串口命令 ID 已淘汰 |

## 串口与宿主机接口

客体帧格式为 `@AGENTOS ` 前缀加一行 UTF-8 JSON，v=1，最多16 KiB。宿主机读取半帧、多帧、混入日志和错误UTF-8；超长帧丢弃到下一换行。命令为无前缀JSON行，最多8192字节，嵌套深度最多8。

```json
{"v":1,"id":1,"command":"start","goal":"检查系统状态","max_rounds":8}
{"v":1,"id":2,"command":"deliver","target_pid":4,"target_instance":3,"kind":2,"payload":{"request_id":12884901889,"action":"tool","name":"get_system_status","params":{}}}
```

命令：start、workload、scenario(context/events)、deliver、snapshot、tool。客体返回 command_result，保留 id/status/result；副作用请求只执行一次。桥接缓存最近8条，且请求/结果总和<=32KiB；已淘汰的旧ID返回ESTALE，不重新执行。

事件含 pid、instance、time_ms；宿主机补 run_id、seq、host_time，服务再补 stream_seq。不要拿宿主机秒与客体 ticks 相减。

| HTTP | 语义 |
| --- | --- |
| GET /api/state | 当前会话、最多32个任务、最近100条事件、采样 |
| GET /api/events?after=N | SSE，使用 stream_seq；支持 Last-Event-ID；游标过旧发送 resync |
| GET /api/export | 当前状态导出，供页面历史回放；完整事件另在磁盘日志 |
| POST /api/action | JSON动作：boot、shutdown、task、cancel、workload、worker_control、scenario、tool |

服务仅绑定回环地址，拒绝非本地 Host/Origin；POST 最多8192字节，明确 application/json。模型配置不会通过接口提供密钥。浏览器动作不支持任意命令、路径下载或外部脚本执行。

## 模型适配

模型接口由内核工具描述生成 JSON Schema，一轮只接受一个 function call，保留 assistant/tool_call_id/tool 关联。模型的 finish 映射到 action=final，要求非空证据集合，引用当前可用 Context seq。工具请求参数与最终文本都再次按1536字节IPC上限约束。

模型请求超时默认60秒，配置范围1..90秒；客体一轮等待最长120秒。外部HTTP错误、连接故障、多个工具调用、错误JSON和无效证据均显式终止或被客体验证拒绝；没有静默脚本降级。

参考：[官方 function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)。具体服务商兼容性和模型质量仍需真实配置后实测。
