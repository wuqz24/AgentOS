# 当前版本交付说明

版本日期：2026-10-19。当前已完成可独立推进的内核、工具、Context、Loop、文件系统、宿主机、页面、验证与材料工作。真实模型API地址和模型名由用户稍后提供；实际模型动态诊断、具体服务故障恢复以及最终结论的正确性仍待验收。

## 直接使用

在AgentOS目录运行 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`，浏览器打开 `http://127.0.0.1:8765`。交付附带正式构建的内核、固件和干净文件系统镜像。Windows需要可用的WSL发行版，当前配置使用AgentOS-Dev；Linux可以运行 `python3 -m host.server`。

先选择“确定性回归（无模型）”启动系统。这会使用真实QEMU与内核数据，固定决策只用于检查机制链路。可创建与暂停CPU负载、运行Context和事件场景、查询诊断文件，以及导出运行记录。完整步骤见[演示流程](演示流程.md)。没有API配置也能完成这些操作。

每次页面启动创建独立磁盘，不修改交付的干净镜像。跨启动文件持久化验证使用专门脚本保留同一磁盘，见 `scripts/test_persistence.py`。页面关闭QEMU与重启清空工作区，是演示重置语义。

## 验证口径

1. 测试构建运行三个客体测试程序，包含逐点分配失败和映射冲突；正式构建确认相应测试入口返回ENOSYS，并完成普通回归。
2. Context压力为10000次追加；生命周期包括100次创建/释放和100次fork/exit/reap；IPC包含1000轮交错。物理页采样用于检查已测路径的资源回收。
3. 文件恢复使用同一镜像四次真实启动，检查属性恢复、校验错误尾识别与后续检查点重建。
4. 两个ABI单元测试、一个磁盘耗尽回滚测试、15项宿主机单元测试通过。桥接、完整服务、取消/迟到隔离、意外断线与实际浏览器有独立记录。
5. 稳定性持续60秒，包含20个负载进程生命周期；预热后空闲物理页恒定。这不是无限期稳定性保证。
6. 各次执行保留当时的构建指纹。性能与宿主机验证各自保存manifest；随后仅清理源码末尾空行并重新生成正式镜像，不重写此前测量数据。
7. PPT经过包结构、原生图表数据、布局检查和逐页渲染检查；没有声称在Microsoft PowerPoint桌面应用中人工打开验证。

复现入口见README。GitHub Actions已改为调用同一验证脚本，不自动发布文档；远端CI尚未触发，本地通过不等于远端通过。工作流依据[checkout官方说明](https://github.com/actions/checkout)与[upload-artifact官方说明](https://github.com/actions/upload-artifact)。

## 唯一外部输入与剩余验收

在 `host/local.env` 填写Base URL、模型名和本地密钥。`python scripts/accept_model.py --check-config`只检查配置；`python scripts/accept_model.py`才执行真实模型调查。

核对至少两次进程采样、诊断文件查询、观察回到下一轮输入、有效Context引用，以及最终文本中的PID、状态、运行量和原因推断。模型只输出流畅文字不足以通过。还需使用所选服务验证故障或取消后的恢复，分别记录API耗时和内核耗时。若服务不兼容标准工具调用格式，则继续调整适配器。

完成后更新B03/B04/E01和汇报中的状态。当前交付状态为“工程机制与确定性闭环已验证，真实模型待验收”，不写成整个项目已通过全部验收。
