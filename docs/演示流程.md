# 演示与复现手册

## 准备

1. 在 AgentOS 项目根目录执行 `powershell -ExecutionPolicy Bypass -File scripts/build.ps1`。
2. 执行 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`，打开 http://127.0.0.1:8765。
3. 真实模型演示前配置 `host/local.env`；尚未配置时使用明确标识的“确定性回归（无模型）”。两种模式都运行真实客体内核。

## 主场景：观察受控负载

1. 启动系统，等待客体已连接。记录空载进程与物理页。
2. 点击“启动负载”，确认出现真实 `agent_worker`。等待两次采样，观察其区间运行占比。
3. 提交：“系统为什么变慢了？请至少两次采样比较进程运行量，按 type=log,tag=diagnostic 检索诊断文件，引用实际证据；暂不执行处置。”
4. 真实模型模式中，检查每轮选择、参数、实际结果和 Context 序号；最终答复必须引用观察。固定模式仅验证链路，不能声称模型已定位故障。
5. 在“文件属性查询”中输入 `type=log,owner=<工作进程PID>`，确认摘要对应这一进程、实例和 busy 状态。
6. 点击“暂停”，等待采样显示工作进程 blocked，检查摘要版本和状态更新；再点击“恢复”或“结束”。不把一次采样解释成通用故障定位能力。

独立模型验收入口为 `python scripts/accept_model.py`。该入口需要有效本地配置，会调用真实API；当前没有配置，因此尚无真实模型通过记录。

## Context 场景

点击“Context 边界”。独立客体 Agent 使用配额3，实际调用6次工具，发生3次淘汰；随后 rollback(1)、追加一次、clear。观察物理槽位、有效长度、累计淘汰数和节点序号。clear 后有效历史为空，先前完整工具记录仍保存在调用轨迹和日志中。

## 心跳与 IPC 场景

点击“心跳与 IPC”。程序分别使用60ms和20ms心跳，停止后等待超时，再 fork 子 Agent；查询确认子进程实际 blocked，发送 IPC 后观察唤醒。展开 loop_event 查看测得间隔、目标进程快照和来源身份。

无事件时不消耗运行量、1000轮交错通信和跨域权限测试见 agent_loop_tests。页面场景用于讲解，不能取代自动化验证。

## 文件场景

1. 受控负载自动产生 `worker-PID-instance.log`，附加 type=log、tag=diagnostic、owner=PID、instance 属性。
2. 用同一条件分别选择“索引”和“扫描基线”，核对相同命中文件，比较 checked/candidates/elapsed_ticks。
3. 暂停工作负载后再次查询，摘要应变为 waiting，版本增加，旧摘要缓存失效。
4. 持久化和损坏尾恢复通过 `scripts/test_persistence.py` 独立验证。页面每次启动使用新的磁盘副本，所以页面“重启”不会自动复用上一次演示磁盘；这是场景重置，不应拿来证明持久化。

## 取消、重启与断线

取消会向客体发送消息，使正在等待模型的 Agent 退出；迟到模型结果被丢弃。已经完成的工具动作不会回滚。关闭系统后页面保留最后记录并标明过期；重新启动产生新的 run_id，任务和采样重置。刷新页面从服务状态恢复，不从JavaScript虚构进度。

完整验证包含故意延迟的确定性响应：先取消，再释放响应，确认没有新增工具执行；随后再次提交任务验证恢复。另有新QEMU运行对旧响应的隔离检查。

## 日志、回放与离线备用

每次运行目录：`artifacts/runs/<时间-后缀>/`。

| 文件 | 内容 |
| --- | --- |
| run.json | 运行标识、真实/固定模式、模型名 |
| serial.log | 原始启动输出和客体事件 |
| events.jsonl | 解码后的客体事件 |
| host-events.jsonl | 模型行动说明、耗时、服务采样、迟到丢弃与客体事件 |
| fs.img | 该次运行的独立磁盘 |

“导出当前记录”保存当前任务、快照和最近事件；“读取历史导出”进入只读回放。完整日志不会因页面队列淘汰而消失。分享记录前核对其中用户目标和客体文件摘要是否适合分享；密钥本身不在记录中。

无需模型的备用材料为 `artifacts/dashboard/desktop.png`、`mobile.png`、`artifacts/service/export.json` 和 `docs/性能实验报告.md`。截图来自真实浏览器与QEMU，但其中的调查为确定性测试，应保留模式标识。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 缺少 kernel.bin/fs.img | 先构建，确认当前目录是 AgentOS 根目录 |
| WSL 找不到发行版 | `wsl -l -v` 检查，将 AGENTOS_WSL_DISTRO 改为可用发行版 |
| 客体握手超时 | 查看对应 serial.log；确保该发行版有 qemu-system-riscv64 |
| 真实任务提示未配置 | 在 host/local.env 填 Base URL 和模型名，密钥仅放本地 |
| API HTTP 401/403/404 | 检查密钥、模型名、Base URL；Base URL 后会追加 /chat/completions |
| 服务不支持工具调用 | 更换支持标准 function calling 的模型，或实现对应适配器；不切换成假模型冒充成功 |
| 页面数据不变 | 检查连接和采样时间，刷新；不要直接打开静态HTML |
| 测试残留目录变大 | 服务关闭后可自行归档不需要的 artifacts/runs；系统不会自动删除历史证据 |

## 建议答辩顺序

说明赛题对应关系 → 演示真实进程与工具 → 展示 Context 边界 → 展示阻塞与唤醒 → 展示文件索引和版本 → 展示三组性能数据 → 说明已验证范围与真实模型待验收项。先展示实际证据，再解释机制；不要把外部模型延迟解释为内核延迟。
