## 当前验证入口

- `bash scripts/verify.sh`：含故障注入的测试构建、原生单元测试、客体回归、四次启动、桥接与服务。
- `bash scripts/verify-production.sh`：正式构建、确认4093–4095不可用、客体回归、从干净磁盘复现三组性能实验。
- `python scripts/verify_host.py --browser`：15项宿主机单元测试、实际串口/服务、60秒稳定性和Chromium页面；记录共同构建指纹及各项日志。
- `python scripts/accept_model.py --check-config`：只检查本地配置；去掉参数才发起真实模型验收，完成后仍需核对结论与观察。

三组实验和页面截图均来自实际运行。性能报告从JSON重新生成，PPT中的图表为可编辑图表，数值取同一统计文件。

## 已确认的实现调整

- UART 输入由桥接进程独占；客体 Agent 输出统一通过一次 write 发送完整帧。这样等待模型时 Agent 可使用内核 IPC 阻塞，而桥接进程无需轮询 UART 与消息队列。
- 定时事件在调度器边界检查，截止时间保存在 PCB 中。避免中断处理期间分配事件对象，也没有需要在退出时回收的额外强引用定时队列。
- 文件身份采用内核目录分配的稳定 ID；easy-fs 当前没有文件删除和重命名，因此名称映射在本项目范围内稳定。工具名统一为 query_files 和 delete_file_attr。
- 属性持久化采用双保留文件：完整性校验的检查点和增量记录。能够识别损坏尾并在后续更新时切换检查点，不声称提供整个 easy-fs 的掉电事务。
- 内核控制台原先将 Unicode 字符强制截为 u8；已修复为 UTF-8 字节输出，并消除跨页字符拆分时的 unwrap 风险。
